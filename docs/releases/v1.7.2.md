# HUB 1.7.2

Ask naturally to speak with another configured character during a voice call.
The call stays connected and the conversation keeps its context. The next reply
uses the chosen character's actual model and personality, rather than continuing
with the initial voice assistant under a different name.

- The voice controls and Telegram call identity follow the current speaker.
- Saved tool permissions remain in effect. New work uses the active character's
  configured target; a main or custom speaker without a separate target uses its
  own worker. Previously started workers keep their original route and policy.
- Character navigation uses the current roster. It does not require a fixed
  phrase, a greeting worker or a search through previous chat histories.
- Ending a call keeps its identity and permission guards until native shutdown
  completes. The saved default for unrelated new chats remains unchanged.

These changes preserve account, character, model and speech settings. Provider
response times, connection retries and model refusals remain provider behavior;
switching characters does not guarantee that a model will accept a request.

Native integration tests use scripted model responses and simulated speech
input. Physical phone and microphone acceptance remains a separate check. See
[voice operation](../voice.md#delegation-and-live-views).
